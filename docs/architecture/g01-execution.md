# G01 execution harness

The bounded closed-world router consumes an entity dictionary and relation grammar, not answers or final test question IDs. It requires unique entity/relation matches and exactly one reviewed fact. Unknown questions, ambiguous routes, conflicting facts and unreviewed claims abstain. This is limited template-based paraphrase routing, not general semantic parsing.

The resident factual-serve CLI returns structured answers and provenance. The benchmark runs either reference-fed or teacher-fed indexed retrieval through the same executable, or a locally launched CPU-only llama.cpp server whose executable and GGUF SHA-256 must match supplied pins. It sends only question text, records raw responses, errors, timings, startup cost, identity and sampled process RSS. Teacher unknown is not inferred from malformed output. No automatic neural fallback is used. The harness does not yet provide whole-system RAM or energy; observations are explicitly gate-ineligible. A process RSS estimate is not whole-system memory. The baseline must be pinned by the operator to a documented quantization and model revision; hashes alone do not prove identity or fairness.

The included two-question smoke fixture is only a regression test. Do not reuse it as independent acceptance evidence. A separately authored 240+ case workload, reviewed corpus and frozen routing grammar are required. Use the same router and corpus scope for both AIR stores, and independently review facts before executing. Record conversion work separately. Reference-fed retrieval must not be omitted even if it outperforms AMT. Actual laptop measurements and independent review remain open.
