# Prototype 03 — local semantic backend and evidence paths
Start an independently installed llama.cpp server with a compatible instruction GGUF (suggested initial experiment Qwen2.5 0.5B/1.5B Instruct Q4), CPU-only, loopback, context 2048 or 4096. Example: llama-server -m /path/model.gguf -ngl 0 -c 4096 --host 127.0.0.1 --port 8080. Set AIR_MODEL_PORT=8080 and AIR_MODEL_NAME to the server model alias. The server retains the model across requests; AIR connects only to fixed IPv4 loopback, disables redirects, bounds response size and time, and validates typed JSON. Supported response_format requires a compatible server; no weights bundled, real-model performance not measured. The mock HTTP test validates the protocol, not semantic accuracy. Model-generated claims require exact source quotes and remain unverified, in a separately created database; anchoring does not establish entailment. Two-hop traversal returns evidence paths, not logically asserted transitive facts.
SQLite VM progress handler imposes approximate per-operation instruction budgets (100 instruction granularity); page cache and payload limits are not RSS limits. Linux wrapper limits process virtual address space and CPU/wall time; separately started model server is not constrained by wrapping AIR. Use systemd/cgroups or equivalent for whole-system budgets. Benchmark script reports combined process peak RSS via GNU time if installed; does not separate backend RSS, measure joules or prove quality-equivalence. Disk store still SQLite reference baseline; source-level alternatives, automatic verification, learned semantic deduplication, full cognitive architecture and real hardware validation remain open.
