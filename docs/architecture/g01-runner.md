# G01 development and execution runner

The prior CI run 45977199094 failed in all six lanes because air-cli used serde derive without declaring serde as a direct dependency. This change adds the missing dependency.

Generate a 240-question synthetic development workload with python3 scripts/g01-development.py NEW_DIR. It contains 200 invented fact mappings in four labelled groups and 40 unsupported entities. This is a scaling and integration test only, not an independently authored real-knowledge dataset. It deliberately uses known routing templates and cannot establish semantic generalisation.

Build with cargo build --release -p air-cli. Run python3 scripts/g01-run.py CORPUS DATASET ROUTER NEW_OUTPUT --development-reference-only for the synthetic reference baseline. For a real comparison omit the development flag and supply --llama-server PATH --gguf PATH --model-sha SHA256 --server-sha SHA256 --teacher-id PINNED_ID. The runner launches the pinned CPU teacher for conversion, shuts it down, then executes reference-fed AIR, teacher-fed AIR and the quantized teacher sequentially. It records input hashes, raw observations, conversion summaries and exact-match counts. The same quantized model is used for conversion and comparison in this initial protocol. The runner assumes a dedicated unused loopback port and a compatible llama.cpp server. No electrical meter is automated, no warm/cold repeats yet, and all outputs remain gate-ineligible until independent review and measured evidence assembly. The independent factual corpus and final test workload remain outstanding.
