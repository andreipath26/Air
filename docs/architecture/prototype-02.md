# Integrated prototype 02
SQLite is a provisional reference backend, not a final choice. Indexed lookup and category joins retrieve only matching records and metadata, rather than deserialising the entire knowledge file. Default cache target 2 MiB; result rows 32; returned UTF-8 payload budget 256 KiB; logical metadata/row steps 100000. These are not hard RSS, VM-instruction, wall-clock or I/O limits; SQLite page cache is advisory. Import is streaming per claim, transactional per record, into a newly created database. An interrupted process may leave a partial database. Normalisation is lexical, tags are keyword-based and claims are unverified. No autonomous fact extraction, semantic deduplication or contradiction resolution. Read-only queries assume a trusted locally created database.
Graphmaster-inspired fast paths match supported question patterns and exact integer arithmetic; unsupported questions abstain. The typed SemanticRouter interface and strict JSON parser permit an external local model to propose a lookup/category/arithmetic route; CLI accepts a supplied JSON proposal only when deterministic routing fails. No embedded SLM or model weights yet. Integer division truncates. No arbitrary commands or code execution. Natural output is simple claim rendering.
The comparative retrieval benchmark measures synthetic indexed SQLite vs in-memory AIR lookup and build time on matching records. It is not an AI benchmark; warm-cache order is fixed, RSS/energy/I/O not measured, no claim of performance superiority. Technology selection, held-out paraphrase tests, actual SLM integration, hard resource enforcement and source-level historical audits remain open.
