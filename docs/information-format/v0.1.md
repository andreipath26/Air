# AIR-IR 0.1 experimental fact snapshot
Magic AIRIR001 (8 bytes), little-endian u32 record count, sorted records containing three length-prefixed UTF-8 strings (subject/relation/object), then category and source sets (u32 count, length-prefixed strings). Lengths count bytes. Canonical identity is the triple with Unicode lowercase and collapsed whitespace; this is lexical normalisation, NOT semantic equivalence. Preserve original first spelling, merge category/source sets, preserve competing objects without treating every multi-valued relation as a contradiction. Limits: 100k records, 64 KiB per field, 1024 entries per set, 64 MiB encoded snapshot. Reject unknown magic, invalid UTF-8, truncated records, duplicate keys/metadata and trailing bytes. This is not a cryptographic integrity mechanism. All indexes are in RAM, not mmap or SSD selective loading. Byte cap on encoded data is not a RAM budget. No executable payloads, timestamps, content hashes, automatic curation or provenance verification yet. Future formats must be independently versioned.
